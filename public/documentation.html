1. Project Overview

SmartInvoice AI is a full-stack web application that automatically extracts structured data from Indian GST invoices and receipts using Optical Character Recognition (OCR). Users upload PDF, PNG, or JPG files, and the system reads every pixel, recognizes text using Tesseract.js, and intelligently parses vendor details, GST information, line items, tax breakdowns, and transport/production details — all with per-field confidence scores.

Problem Solved

Manual data entry from invoices is slow, error-prone, and expensive. This tool automates the entire pipeline — from document upload to OCR extraction to structured data export — specifically tailored for Indian GST invoice formats.

5. Data Processing Flow

When a user uploads a document, the system follows a 4-step pipeline:

1
Document Loading
File is loaded into memory. PDFs are detected by MIME type or extension. Images (PNG/JPG) are loaded directly.
2
OCR Text Extraction
For PDFs: PDF.js renders each page to a canvas at 2x scale → Tesseract.js OCRs each canvas page.
For Images: Image is drawn to canvas (max 2000px) → Tesseract.js OCRs the canvas.
Progress is reported in real-time to the UI.
3
Structured Field Parsing
Raw OCR text is parsed using multi-pattern regex extractors. Each field (GSTIN, PAN, amounts, dates, line items) is extracted with a confidence score based on match quality. Missing values are auto-computed where possible (e.g., total tax = CGST + SGST + IGST).
4
Validation & Confidence Scoring
Overall confidence is computed as the average of all field confidences. Fields below 75% confidence are highlighted in amber. Results are displayed in an editable form for manual review.

8. OCR Engine Deep Dive

How Tesseract.js Works in the Browser

Tesseract.js is a pure JavaScript port of the Tesseract OCR engine. It runs in a Web Worker to avoid blocking the UI thread. The engine downloads language data (English) on first use, then processes canvas images to recognize text.

// ocrEngine.ts — Core OCR function async function ocrCanvas(canvas: HTMLCanvasElement): Promise<string> { const result = await Tesseract.recognize(canvas, 'eng', { logger: (m) => { if (m.status === 'recognizing text') { onProgress({ phase: 'Recognizing text', progress: m.progress }); } } }); return result.data.text; }

PDF Processing Pipeline

  1. File is read as ArrayBuffer
  2. PDF.js loads the document and gets page count
  3. Each page is rendered to a canvas at 2x scale for better OCR accuracy
  4. Canvas is passed to Tesseract.js for text recognition
  5. All page texts are joined with double newlines
  6. Progress is reported per-page to the UI

Image Processing Pipeline

  1. Image is loaded into an Image object
  2. Drawn to canvas (max dimension 2000px to prevent memory issues)
  3. Canvas is passed to Tesseract.js
  4. Recognized text is returned

Python Backend OCR (Optional)

The Python backend mirrors the same logic using pytesseract for OCR and pdf2image for PDF rasterization. It also includes an optional EasyOCR backend (neural network-based) for higher accuracy, and a pluggable extract_with_vision_llm() abstraction for cloud Vision LLM integration (GPT-4V, Gemini, Claude Vision).

Why 2x Scale for PDF Rendering?

OCR accuracy depends on image resolution. At 1x scale, text in PDFs can be too small for Tesseract to recognize accurately. Rendering at 2x scale doubles the pixel density, giving Tesseract more data to work with — significantly improving recognition quality.

9. Invoice Parser — Indian GST Extraction

Regex-Based Multi-Pattern Extraction

The parser (invoiceParser.ts) uses a fallback pattern system: for each field, multiple regex patterns are tried in priority order. The first match wins, and confidence decreases with each failed attempt.

// GSTIN extraction — 4 patterns tried in order function extractGSTIN(text: string): FieldConfidence { const result = tryPatterns(text, [ /GSTIN\s*[:.]?\s*([0-9]{2}[A-Z]{5}\d{4}[A-Z]\d[A-Z]\d)/i, // "GSTIN: 27AABCF8078M1Z8" /\b([0-9]{2}[A-Z]{5}\d{4}[A-Z]\d[A-Z]\d)\b/, // Bare GSTIN anywhere /GST\s*(?:No|Number|ID)?\s*[:.]?\s*([0-9]{2}[A-Z]{5}\d{4}...)/i, // "GST No: ..." ]); if (result) return field(result.match.toUpperCase(), confidenceFromIndex(result.index, 0.93)); return field('', 0.3); }

Auto-Computation Logic

  • Subtotal: If missing, computed as sum of all line item totals
  • Total Tax: If missing, computed as CGST + SGST + IGST
  • Grand Total: If missing, computed as Subtotal + Total Tax
  • Line Total: Computed as Quantity × Unit Price × (1 − Discount/100)

Date Normalization

Indian invoices use DD/MM/YYYY format. The parser detects and normalizes multiple formats to ISO (YYYY-MM-DD): DD/MM/YYYY, DD-MM-YYYY, YYYY-MM-DD, YYYY/MM/DD, and "Month DD, YYYY" (e.g., "March 15, 2024").

Line Items Extraction

The parser identifies the line items table by finding a header row containing keywords like "Description" + "Qty/HSN/Rate", then parses each row until it hits a total/tax keyword. Each row is parsed with 3 regex patterns of decreasing specificity.

13. Interview Questions & Answers

Q: What is this project and what problem does it solve?
SmartInvoice AI is an OCR-based invoice processing tool that automatically extracts structured data from Indian GST invoices. It solves the problem of manual data entry — instead of typing invoice details by hand, users upload a PDF or image and the system reads it using Tesseract OCR, parses GST-specific fields like GSTIN, HSN codes, and CGST/SGST/IGST, and presents everything in an editable form with confidence scores.
Q: Which technologies did you use and why?
Frontend: React 18 with TypeScript for type safety, Vite for fast builds, Tailwind CSS for responsive styling. For OCR: Tesseract.js runs directly in the browser via Web Workers — no server needed. PDF.js (pdfjs-dist) renders PDF pages to canvas for OCR. SheetJS (xlsx) handles Excel export. An optional Python FastAPI backend with pytesseract is available for server-side processing. I chose client-side OCR for privacy, zero infrastructure cost, and instant processing.
Q: How does the OCR pipeline work?
For PDFs: PDF.js renders each page to a canvas at 2x scale (for better accuracy), then Tesseract.js OCRs each canvas. For images: the image is drawn to canvas (max 2000px), then OCR'd. The raw text from all pages is joined and passed to the parser. Progress is reported in real-time to the UI with a 4-step animation: Loading → OCR → Parsing → Validation.
Q: How do you extract structured fields from raw OCR text?
I built a regex-based multi-pattern extraction system. For each field (GSTIN, PAN, amounts, dates, etc.), multiple regex patterns are tried in priority order. The first match wins and confidence decreases with each failed pattern. For example, GSTIN has 4 patterns: "GSTIN: XXX", bare GSTIN pattern, "GST No: XXX", etc. I also auto-compute missing values — if total tax is empty but CGST+SGST+IGST are present, it calculates the sum.
Q: What is the confidence scoring system?
Every extracted field gets a confidence score from 0 to 1 based on match quality. If the first regex pattern matches, confidence is ~95%. Each subsequent failed pattern reduces it by 5%. Fields below 75% get amber highlighting with a "please verify" warning. The overall document confidence is the average of all field scores, displayed prominently in the export toolbar.
Q: How is this tailored for Indian invoices?
The parser specifically handles Indian GST format: GSTIN (15-character tax ID with state code), PAN (10-character), CIN, CGST/SGST (intra-state) vs IGST (inter-state), HSN codes for goods, Place of Supply with state code, DD/MM/YYYY date format, ₹ symbol for amounts, Indian units (NOS, CUM, KG, SET), and amount-in-words. The sample invoices include real Indian companies like Reliance, Tata Motors, Flipkart, and UltraTech.
Q: What are the detail sections?
Beyond standard fields, the system extracts three expandable detail sections from industrial invoices: Invoice & Order Details (PO number, order number, DC number), Delivery & Transport (vehicle number, driver name, e-way bill), and Production Details (cement type, mix design, slump, W/C ratio, admixture). These are specifically for industrial invoices like concrete delivery bills.
Q: How does the export work?
Three formats: JSON (full structured data), CSV (flat key-value with line items and sections), and Excel (multi-sheet workbook — Summary sheet with all fields, Line Items sheet, and separate sheets for each detail section). Column widths are auto-sized. There's also a Copy JSON button for clipboard.
Q: What is the application's state management approach?
I use React's built-in useState and useCallback hooks. The app has a 3-phase state machine: upload → processing → review. The active document (with extracted invoice and raw OCR text) is held in a single state object. All child components are controlled — they receive data via props and report changes via callbacks, keeping the state flow unidirectional.
Q: What challenges did you face?
1) OCR accuracy on low-quality scans — solved by rendering PDFs at 2x scale. 2) Parsing Indian date formats (DD/MM vs MM/DD ambiguity) — solved by validating day ≤ 31 and month ≤ 12. 3) Distinguishing CGST/SGST (intra-state) vs IGST (inter-state) — the parser tries all three and shows whichever is present. 4) Handling multi-page PDFs — each page is OCR'd separately and text is joined. 5) Regex escaping issues in the parser — solved with a dedicated escapeRegex helper function.
Q: How would you scale this for production?
1) Move OCR to the Python backend with EasyOCR or a Vision LLM for higher accuracy. 2) Add Supabase for storing extraction history and user accounts. 3) Implement batch processing for multiple invoices. 4) Add a GSTIN validation API to verify supplier details. 5) Integrate with accounting software (Tally, Zoho Books) via their APIs. 6) Add e-way bill auto-generation. 7) Implement GST return filing data preparation (GSTR-1, GSTR-3B).
