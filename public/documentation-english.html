1 What Is This Project?

SmartInvoice AI is a web application that automatically reads information from Indian GST invoices and receipts. In simple terms: you have a paper invoice or a PDF invoice on your computer. You upload it to this app, and the app reads all the text from it — vendor name, GST number, amounts, tax breakdown, line items, everything — and displays it in a clean, editable form. No manual data entry needed.

What Problem Does This Solve?

Every day, Indian companies receive thousands of invoices. The accounts team has to manually type in every detail from each invoice — vendor name, GST number, amounts, tax amounts, line items, and more. This process is slow, prone to typing errors, and wastes a lot of time. SmartInvoice AI does all of this automatically in seconds.

Why Scan In The Browser? (Why Not A Server?)

  • Zero infrastructure cost — no server to maintain, no cloud bills to pay
  • Complete privacy — your document never leaves your computer
  • Instant processing — no waiting for data to travel to a server and back

This keeps everything organized and consistent.

5 How Does The Scanning Work?

What Is The Scanning Engine?

The scanning engine (called Tesseract.js) is an open-source tool that reads text from images. It runs inside your browser in a background thread, which means the app stays responsive and smooth while scanning is happening — you can still interact with the page. The first time you use it, it downloads a small English language pack, and after that it can read text from any image or PDF page.

How Are PDFs Processed?

  1. The PDF file is read into memory
  2. A PDF reader tool loads the document and counts the pages
  3. Each page is rendered onto a canvas at double resolution (for better accuracy)
  4. The canvas image is passed to the scanning engine
  5. Text from each page is recognized separately
  6. All text from all pages is combined together
  7. Progress is shown on screen in real-time

How Are Images Processed?

  1. The image is loaded into the page
  2. It's drawn onto a canvas (limited to 2000 pixels on the longest side, to save memory)
  3. The canvas is passed to the scanning engine
  4. The recognized text is returned
Why Double Resolution?

Scanning accuracy depends heavily on image resolution. At normal size, the text in a PDF is too small for the scanning engine to read reliably. By doubling the resolution, we give the engine twice as many pixels to work with, which dramatically improves how accurately it recognizes each character.

What About The Python Server Option?

The Python server follows the same logic but uses Python-based tools instead. It can use the same scanning engine via a Python wrapper, or it can use an alternative neural-network-based engine (EasyOCR) that is more accurate but slower. There's also a placeholder for connecting cloud-based vision AI models (like GPT-4V or Gemini Vision) in the future, which would offer even higher accuracy for complex or handwritten documents.

6 How Does Information Get Extracted?

Once the scanning engine produces raw text, the app needs to find specific pieces of information in that text. It does this using a pattern-matching system. For each field (like GST number, invoice number, amounts), there are multiple search patterns tried in order of priority. The first one that matches wins, and the confidence score decreases slightly for each pattern that had to be tried before finding a match.

Smart Auto-Calculations

If some values are missing, the app calculates them automatically: Subtotal: if empty, adds up all line item totals. Total Tax: if empty, adds CGST + SGST + IGST. Grand Total: if empty, adds Subtotal + Total Tax. Line Total: Quantity × Unit Price × (1 − Discount%).

Date Handling (Indian Format)

Indian invoices typically use the DD/MM/YYYY date format. The app detects multiple date formats and converts them all to a standard format (YYYY-MM-DD): DD/MM/YYYY, DD-MM-YYYY, YYYY-MM-DD, YYYY/MM/DD, and even text dates like "March 15, 2024". It validates that the day is 31 or less and the month is 12 or less to avoid mixing up days and months.

How Are Line Items Found?

The app looks for a table header row containing words like "Description" along with "Qty", "HSN", or "Rate". Once it finds the header, it reads each row below it until it hits a row containing words like "Total", "Tax", or "Subtotal". Each row is parsed to extract the description, HSN code, quantity, unit, rate, and line total.

8 Export Options & Sample Invoices

How Does Export Work?

You can export the extracted data in 3 formats:

  • JSON: A structured data file containing all fields, line items, and detail sections. Ideal for programmers or importing into other systems.

  • Excel (XLSX): A multi-sheet workbook — one sheet for the summary (all fields), one for line items, and separate sheets for each detail section. Column widths are automatically sized.

There's also a Copy JSON button that copies all the data to your clipboard instantly.

10 Questions & Answers

Q1: What is this project and what problem does it solve?
SmartInvoice AI is a scanning-based invoice processing tool that automatically extracts data from Indian GST invoices. The problem is that companies receive thousands of invoices daily, and the accounts team has to manually type in every detail — vendor name, GST number, amounts, tax breakdown, line items. This is slow and error-prone. Our tool does all of this automatically: upload a document, the app scans it, extracts the data, and lets you export it in one click.
Q2: What technologies did you use and why?
For the user interface: React with TypeScript for safety, Vite for fast builds, and Tailwind CSS for responsive styling. For scanning: Tesseract.js runs right in the browser — no server needed. PDF.js renders PDF pages for scanning. SheetJS handles Excel export. There's an optional Python backend using FastAPI for server-side processing. I chose browser-based scanning because it means zero infrastructure cost, complete privacy (documents never leave your device), and instant processing with no network delay.
Q3: How does the scanning pipeline work?
For PDFs: each page is rendered onto a canvas at double resolution (for accuracy), then the scanning engine reads text from each canvas page. For images: the image is drawn onto a canvas (limited to 2000 pixels to save memory), then scanned. All text from all pages is combined and passed to the information extractor. Progress is shown in real-time on screen across 4 stages: Loading, Scanning, Extracting, and Validating.
Q4: How do you get structured fields from raw scanned text?
A pattern-matching system with multiple search patterns per field, tried in priority order. The first match wins, and confidence drops 5% for each pattern that had to be tried before finding a match. For example, the GST number has 4 patterns: "GSTIN: XXX", a bare GST number pattern, "GST No: XXX", and so on. Missing values are also auto-calculated — if total tax is empty, it adds CGST + SGST + IGST automatically.
Q5: What is the confidence scoring system?
Every extracted field gets a confidence score from 0 to 100%. The first pattern match gives about 95% confidence. Each failed pattern drops it by 5%. Scores of 90% and above show green, 75-89% show amber, and below 75% show red. Low-confidence fields display a "please verify" warning. The overall document confidence is the average of all field scores, displayed prominently in the export toolbar.
Q6: How is this specifically tailored for Indian invoices?
The app handles Indian-specific fields: GSTIN (15-character tax ID with state code), PAN (10-character), CIN, CGST/SGST (for intra-state sales) vs IGST (for inter-state sales), HSN codes for goods classification, Place of Supply with state code, DD/MM/YYYY date format, the ₹ symbol for amounts, Indian units (NOS, CUM, KG, SET), and amounts written in words. The 4 sample invoices feature real Indian companies: Reliance, Tata Motors, Flipkart, and UltraTech Cement.
Q7: How does the export system work?
Three formats: JSON (full structured data for programmers), CSV (flat spreadsheet with field-value pairs, line items, and detail sections), and Excel (multi-sheet workbook with a Summary sheet for all fields, a Line Items sheet, and separate sheets for each detail section). Column widths are auto-sized for readability. There's also a Copy JSON button for instant clipboard copying.
Q8: What challenges did you face and how did you solve them?
1) Low scanning accuracy on poor-quality scans — solved by rendering at double resolution. 2) Indian date format ambiguity (DD/MM vs MM/DD) — solved with validation (day must be 31 or less, month 12 or less). 3) Distinguishing CGST/SGST from IGST — the extractor tries all three and shows whichever is present. 4) Multi-page PDFs — each page is scanned separately and text is combined. 5) Large images causing memory issues — canvas is limited to 2000 pixels on the longest side.
Q9: How would you scale this for production?
1) Move scanning to the Python server with EasyOCR or cloud vision AI for higher accuracy. 2) Add user accounts and save extraction history using a database. 3) Support batch processing for multiple invoices at once. 4) Add GST number validation against government APIs for supplier verification. 5) Integrate with accounting software like Tally or Zoho Books. 6) Auto-generate e-way bills. 7) Prepare data for GST return filing (GSTR-1, GSTR-3B).
