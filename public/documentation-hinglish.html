1 Ye Project Kya Hai?

SmartInvoice AI ek aisa web application hai jo Indian GST invoices aur receipts se automatic data extract karta hai. Simple bhasha me samjhe to — aapke paas jo paper invoice ya PDF invoice hai, usko upload karo, aur ye app usme se saara data nikal kar ek form me dikhayega. Data entry manually karne ki zaroorat nahi.

Asli Problem Kya Hai?

Indian companies me har din hazaaron invoices aate hain. Accounts team ko har invoice ka data manually enter karna padta hai — vendor ka naam, GSTIN, amounts, tax breakdown, line items, sab. Ye process slow hai, errors hote hain, aur bahut time waste hota hai. SmartInvoice AI ye sab automatic kar deta hai.

5 OCR Engine Detail (Text Kaise Nikalta Hai)

Tesseract.js Kya Hai?

Tesseract.js ek open-source OCR engine hai jo JavaScript me likha gaya hai. Ye browser me Web Worker me chalta hai — isse UI thread block nahi hota, user ko smooth experience milta hai. Pehli baar use karne pe English language data download hota hai, phir canvas images se text recognize karta hai.

PDF Processing Kaise Hota Hai?

  1. File ko ArrayBuffer me read kiya jata hai
  2. PDF.js document load karta hai aur page count pata lagata hai
  3. Har page ko 2x scale pe canvas pe render kiya jata hai (accuracy ke liye)
  4. Canvas ko Tesseract.js ko pass kiya jata hai
  5. Har page ka text alag se recognize hota hai
  6. Saara text \n\n se join ho jata hai
  7. Progress real-time me UI pe dikhta hai

Image Processing Kaise Hota Hai?

  1. Image ko Image object me load kiya jata hai
  2. Canvas pe draw kiya jata hai (max 2000px dimension — memory issues se bachne ke liye)
  3. Canvas ko Tesseract.js ko pass kiya jata hai
  4. Recognized text return ho jata hai
// OCR Engine ka core function async function ocrCanvas(canvas: HTMLCanvasElement): Promise<string> { const result = await Tesseract.recognize(canvas, 'eng', { logger: (m) => { if (m.status === 'recognizing text') { onProgress({ phase: 'Recognizing text', progress: m.progress }); } } }); return result.data.text; }
2x Scale Kyun Use Karte Hain?

OCR accuracy image resolution pe depend karta hai. 1x scale pe PDF ka text Tesseract ke liye bahut chhota hota hai. 2x scale pe pixel density double ho jati hai — Tesseract ko zyada data milta hai aur recognition bahut better hota hai.

Python Backend OCR (Optional)

Python backend same logic follow karta hai but pytesseract (Python wrapper) use karta hai. PDF ke liye pdf2image use hota hai. Ek optional EasyOCR backend bhi hai jo neural network use karta hai — zyada accurate but slower. Saath me ek extract_with_vision_llm() function bhi hai jo future me GPT-4V ya Gemini Vision jaise cloud models ke liye plug kar sakte hain.

6 Invoice Parser (Text Se Data Kaise Nikalta Hai)

OCR se jo raw text aata hai, usme se fields extract karne ke liye regex-based multi-pattern system banaya gaya hai. Har field ke liye multiple regex patterns hain — priority order me try hote hain. Pehla match jeet jata hai, aur confidence har failed pattern ke saath kam hota jaata hai.

Example: GSTIN Kaise Extract Hota Hai

// 4 patterns try hote hain — priority order me function extractGSTIN(text: string): FieldConfidence { const result = tryPatterns(text, [ // Pattern 1: "GSTIN: 27AABCF8078M1Z8" — highest confidence (93%) /GSTIN\s*[:.]?\s*([0-9]{2}[A-Z]{5}\d{4}[A-Z]\d[A-Z]\d)/i, // Pattern 2: Kahi bhi 15-char GSTIN pattern — confidence 88% /\b([0-9]{2}[A-Z]{5}\d{4}[A-Z]\d[A-Z]\d)\b/, // Pattern 3: "GST No: ..." ya "GST Number: ..." — confidence 83% /GST\s*(?:No|Number|ID)?\s*[:.]?\s*([0-9]{2}...)/i, ]); if (result) return field(result.match.toUpperCase(), confidenceFromIndex(result.index, 0.93)); return field('', 0.3); // No match — 30% confidence }

Auto-Computation Logic (Khud Calculate Karna)

Agar Kuch Values Missing Hain To Khud Calculate Ho Jate Hain

Subtotal: Agar empty hai aur line items hain, to sab line items ka sum le leta hai.
Total Tax: Agar empty hai, to CGST + SGST + IGST ka sum le leta hai.
Grand Total: Agar empty hai, to Subtotal + Total Tax le leta hai.
Line Total: Quantity × Unit Price × (1 − Discount/100)

Date Normalization (Indian Format)

Indian invoices me date DD/MM/YYYY format me hota hai. Parser multiple formats detect karta hai aur sabko ISO format (YYYY-MM-DD) me convert karta hai: DD/MM/YYYY, DD-MM-YYYY, YYYY-MM-DD, YYYY/MM/DD, aur "March 15, 2024" jaise text dates bhi.

Line Items Kaise Parse Hote Hain?

Parser line items table ko identify karta hai — ek header row dhundta hai jisme "Description" aur "Qty/HSN/Rate" jaise keywords hon. Phir har row ko 3 regex patterns se parse karta hai (decreasing specificity order me). Jab tak "Total" ya "Tax" keyword nahi aata, tab tak rows parse hote hain.

10 Interview Questions & Answers

Q1: Ye project kya hai aur kya problem solve karta hai?
SmartInvoice AI ek OCR-based invoice processing tool hai jo Indian GST invoices se automatic data extract karta hai. Problem ye hai ki companies me har din hazaaron invoices aate hain aur accounts team ko manually data entry karni padti hai — vendor naam, GSTIN, amounts, tax breakdown, line items sab. Ye slow hai aur errors hote hain. Humara tool ye sab automatic karta hai — upload karo, OCR chal jata hai, data extract ho jata hai, aur ek click me export ho jata hai.
Q2: Kaun si technologies use ki aur kyun?
Frontend: React 18 with TypeScript (type safety), Vite (fast builds), Tailwind CSS (responsive styling). OCR: Tesseract.js browser me chalta hai — koi server nahi chahiye. PDF.js PDF pages ko canvas pe render karta hai. SheetJS Excel export ke liye. Optional Python backend FastAPI + pytesseract se server-side OCR ke liye. Maine client-side OCR choose kiya kyunki — zero infrastructure cost, privacy (document browser se bahar nahi jata), aur instant processing (no network round-trip).
Q3: OCR pipeline kaise kaam karta hai?
PDF ke liye: PDF.js har page ko 2x scale pe canvas pe render karta hai (accuracy ke liye), phir Tesseract.js har canvas page ka text recognize karta hai. Image ke liye: image canvas pe draw hota hai (max 2000px), phir OCR hota hai. Saara text join ho jata hai aur parser ko pass ho jata hai. Progress real-time me UI pe dikhta hai — 4 steps: Loading → OCR → Parsing → Validation.
Q4: Raw OCR text se structured fields kaise extract hote hain?
Regex-based multi-pattern extraction system banaya hai. Har field (GSTIN, PAN, amounts, dates, etc.) ke liye multiple regex patterns hain priority order me. Pehla match jeet jata hai, confidence har failed pattern ke saath 5% kam hota hai. Example: GSTIN ke 4 patterns hain — "GSTIN: XXX", bare GSTIN pattern, "GST No: XXX", etc. Missing values bhi auto-compute hote hain — agar total tax empty hai to CGST+SGST+IGST ka sum le leta hai.
Q5: Confidence scoring system kya hai?
Har extracted field ko 0 se 1 ke beech confidence score milta hai. Pehla regex pattern match ho to ~95%. Har failed pattern pe 5% kam. 90%+ green, 75-89% amber, <75% red. Low confidence wale fields pe "please verify" warning dikhti hai. Overall document confidence saara fields ka average hota hai — ye ExportToolbar me prominent display hota hai.
Q6: Ye Indian invoices ke liye specifically kaise tailored hai?
Parser specifically Indian GST format handle karta hai: GSTIN (15-char tax ID with state code), PAN (10-char), CIN, CGST/SGST (intra-state) vs IGST (inter-state), HSN codes for goods, Place of Supply with state code, DD/MM/YYYY date format, ₹ symbol for amounts, Indian units (NOS, CUM, KG, SET), aur amount-in-words. Sample invoices me real Indian companies hain — Reliance, Tata Motors, Flipkart, UltraTech.
Q7: Export system kaise kaam karta hai?
3 formats: JSON (full structured data), CSV (flat key-value with line items and sections), aur Excel (multi-sheet workbook — Summary sheet with all fields, Line Items sheet, aur separate sheets for each detail section). Column widths auto-sized hote hain. Copy JSON button bhi hai jo clipboard pe copy karta hai.
Q8: State management ka approach kya hai?
React ke built-in useState aur useCallback hooks use kiye hain. App me 3-phase state machine hai: upload → processing → review. Active document (extracted invoice + raw OCR text) ek single state object me store hota hai. Saare child components controlled hain — props se data aata hai, callbacks se changes report hote hain. Data flow unidirectional hai.
Q9: Kya challenges aaye aur kaise solve kiye?
1) OCR accuracy low-quality scans pe — 2x scale se solve kiya. 2) Indian date format (DD/MM vs MM/DD ambiguity) — day ≤31 aur month ≤12 validation se. 3) CGST/SGST vs IGST distinction — parser teeno try karta hai aur jo present hai wo dikhata hai. 4) Multi-page PDFs — har page alag OCR hota hai. 5) Regex escaping issues — dedicated escapeRegex helper function se solve kiya.
Q10: Production me kaise scale karenge?
1) OCR ko Python backend pe move karenge EasyOCR ya Vision LLM ke saath. 2) Supabase add karenge extraction history aur user accounts ke liye. 3) Batch processing for multiple invoices. 4) GSTIN validation API for supplier verification. 5) Accounting software integration (Tally, Zoho Books). 6) E-way bill auto-generation. 7) GST return filing data preparation (GSTR-1, GSTR-3B).
